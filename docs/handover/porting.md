# 适配到其它内核

目标是把这套面板的思路搬到 sing-box 等其它内核上。
**先读 [排障手册](troubleshooting.md) 的三条经验**, 它们跨内核通用。

---

## 这套东西真正可复用的是「结构」, 不是代码

值得搬过去的:

1. **片段 + 合并** —— 每个节点一个文件, 改一个不影响其它
2. **双层校验** —— 自己的校验器 + 内核自己的校验
3. **机械门禁** —— 每修一处「两处必须一致」的问题, 就配一个门
4. **CDN 打通 + 回源** 的那套抽象
5. **排障顺序** —— 见排障手册末尾的通用顺序

不值得搬的: 具体协议模板(每个内核的字段都不一样)。

---

## 跨内核的坑(实测)

### 1. 内核对不认识的键是**静默忽略**的

这是最关键的一条。mihomo 里 `xhttp-config` 写在 trojan 的 listener 上,
**不报错, 直接忽略**, listener 退化成裸 TCP, 客户端却按 xHTTP 去连 ——
必然连不上, 而且症状是「自家校验器报了个警告」, 很容易被忽略。

所以适配新内核时, **必须先写一个「内核认哪些键」的校验器**。
这个校验器比任何文档都可靠。

### 2. 配置测试通过 ≠ 能启动

mihomo 的 `mihomo -t` 对**越界证书路径放行**, 实际启动静默失败。
别的内核大概率也有类似的两层。

对策: 端口绑定核对必须是**所有新增路径的共同出口**, 不是某一个函数里的可选检查。

### 3. 传输能力矩阵要自己测, 不要抄

mihomo 的实际能力:

| 组合 | 状态 |
|---|---|
| trojan + h2 | **内核没有这个传输** |
| vless + xhttp | 有,但 `xhttp-config` 只在 **vless 的 listener** 里存在 |
| vmess/trojan + xhttp | **写成 listener 会被静默忽略** → 死节点 |
| REALITY + ws | 实测 0/5 |
| REALITY + tcp/grpc/xhttp | 可用 |

**"别的内核支持"不等于"这个内核在这个协议上支持"。**
适配时先做一张**协议 × 传输**的实测表, 再决定生成哪些组合。

宁可少发几个档位, 也不能发"永远连不上"的死节点。

## 建议的落地顺序

### 阶段 1: 最小可用

目标: 能生成、能校验、能跑起来。

1. 抄目录结构 (`lib/` `conf/` `share/` `tools/`)
2. 抄 `lib/env.sh` 的**环境探测**部分(服务名、路径、内核版本)
3. **先写 validate 类的校验器** —— 枚举内核认的键
4. 先支持 2-3 个协议, 走通完整链路
5. 把 `tools/check_all.sh` 的门禁机制建起来

### 阶段 2: 面板化

把阶段 1 的脚本接进交互菜单。**这一步最容易出错**, 因为:

- 菜单项编号容易记错 → 用 `check_menu_ids.sh` 校验
- 输入序列容易错位 → 启动延迟 8 秒

### 阶段 3: CDN

CDN 这层是最容易出玄学问题的地方, 按这个顺序做:

1. **先不用 CDN**, 把直连跑通
2. 加 WS 回源(最简单, 101 就算成功)
3. 再加 gRPC(200 算成功)
4. 最后加 ECH —— **ECH 一定要放到最后**, 因为它的失败症状
   和"内核坏了"完全一样, 会把排查带偏

> 本项目就是反过来做的: 先加了 ECH, 结论"实测连不上"就把 ECH 关了,
> 后面查出来根因在 DNS。这个错误路径的代价是三轮排查。

### 阶段 4: 客户端

客户端的坑比服务端多:

- DNS 配置的每个开关都会影响 ECH, 而且**全是静默失败**
- 多来源配置要一起改(生成处 + 菜单预设)
- 节点名撞车

## 通用原则(跨内核)

### 默认值错了比默认值缺失更糟

「DNS 管理」里那个预设, 看起来是最安全的一步, 实际把 ECH 关掉了。
用户点它的时候是**带着"让我更安全"的预期**的。

所以: **每个默认值都要问一遍"它在什么情况下会反着来"**。

### 探针要问,不要假设

每次得出"某功能坏了"之前, 先问一句: **我测的是不是我以为的那个东西?**

本项目的五个实例:

| 测的 | 以为测的 |
|---|---|
| nginx 返回 200 | 整条链路通 |
| 路由器 DNS 查 type 65 | 解析器不支持 type 65 |
| 重启后立刻查端口 | 端口绑不上 |
| for 循环里 `${*// /-}` | 空格换了横线 |
| grep 文件名前缀 | 匹配到了对应条目 |

### 故障节点比缺失节点更糟

缺失节点: 用户一眼看出少了。
故障节点: 用户得逐个排查, 才知道它是不是坏了。

移出默认档位的判断依据就是这个。**覆盖价值已经被别的节点满足的, 就别发。**

## 数字参考

mihomo--core 走到"基本够用"花了:

- 328 次提交
- 约 21000 行 (shell + python)
- 13 项机械门禁
- 3 台机器 (1 测试 + 1 生产 + 1 客户端)

**其中绝大部分工作量不在写功能, 而在「发现问题」和「写门禁防止它再犯」。**
新内核如果沿用这套做法, 时间大头也会在这里。心里有个数比较好。
